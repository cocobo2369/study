# ✅ 규칙 9. **직접 사용 시 헤더 직접 include, 전이적 include 제한**

---

## 🔹 1. 요약 설명

* 어떤 컴포넌트 A가 다른 컴포넌트 B의 기능을 **직접 사용**한다면,
  A는 **B의 헤더 파일을 직접 include 해야 합니다.**
* **중간에 끼어 있는 다른 컴포넌트 C가 B를 include한다고 해서 A가 C만 include하면 안 됩니다.**
* 다만 **public 상속**처럼, 반드시 B까지 연결되어야 하는 경우에만 예외적으로 전이적 include가 허용됩니다.

---

## 🔹 2. 상세 설명

### 📌 왜 이렇게 해야 하나?

* 직접 사용하는 컴포넌트의 헤더를 명확히 포함해야:

  * **코드 의존성이 명확**
  * 다른 컴포넌트 수정 시 **예상치 못한 빌드 실패 방지**
  * **불필요한 빌드 확산 최소화**

### 📌 전이적 include란?

예를 들어 컴포넌트 C가 B를 포함하고 있고, A가 C를 포함만 했는데 B의 기능을 쓴다면:

```plaintext
A.cpp
 ↓  (include)
C.h   (include)
 ↓
B.h
```

➡ A가 B를 사용하면서도 B.h를 직접 포함하지 않음 → **의존 관계 불명확**

### 📌 이렇게 하면 어떤 문제가 발생?

* 나중에 C가 B.h 포함을 삭제하면 A가 갑자기 빌드 에러 발생
* 코드 상에서는 A가 B를 사용하고 있는데, include가 없으니 **이해하기 어려운 코드 구조**

---

### ⚠️ 전이적 include가 허용되는 경우 (예외)

✔️ public 상속으로 **컴파일 타임에 반드시 종속**되는 경우는 예외:

```cpp
// C.h
#include "B.h"

class C : public B {};  // public 상속이므로, C를 쓴다는 건 B도 함께 쓴다는 뜻
```

이 경우 A가 C만 include해도 B는 반드시 필요하므로 허용됩니다.

---

## 🔹 3. 예시

### ❌ 잘못된 경우 (전이적 include 사용)

```cpp
// B.h
class B {};

// C.h
#include "B.h"

class C {
public:
    void useB(B b);
};

// A.cpp
#include "C.h"

void f(B b) {   // B를 직접 사용하지만 B.h는 포함 안 함 → 잘못된 예시
    C c;
    c.useB(b);
}
```

✔️ A.cpp 에서 B를 쓰고 있으므로 **B.h를 직접 포함해야 함**

---

### ✅ 잘된 경우 (직접 include)

```cpp
// A.cpp
#include "C.h"
#include "B.h"   // 직접 포함

void f(B b) {
    C c;
    c.useB(b);
}
```

| 원칙               | 설명             |
| ---------------- | -------------- |
| 직접 사용하는 헤더       | 반드시 직접 include |
| 중간 컴포넌트 포함에 의존   | ❌ 금지           |
| public 상속 관계만 예외 | ✅ 허용 가능        |

➡ 이렇게 하면 **컴파일 타임 의존성, 빌드 의존성, 코드 관리 의존성이 모두 일치**합니다.
